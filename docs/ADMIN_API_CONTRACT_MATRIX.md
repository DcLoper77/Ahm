# Admin Control Panel API contract matrix

Snapshot: 2026-09-24. This matrix describes the supported browser UI in this repository and the
dedicated Fastify Admin plane in `D:\API - Havenerr`. The browser only requests same-origin
`/admin/v1/*`; Next.js rewrites those requests to `https://api.havenerr.com/admin/v1/*`.

## Shared request and response rules

| Code  | Authentication and headers                                                                                                                                                                                                        |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R** | Read: `credentials: include`, no-store fetch, host-only `hv_admin_sess` cookie. No mutation CSRF or idempotency header.                                                                                                           |
| **M** | Mutation: `credentials: include`, host-only `hv_admin_sess`, readable `hv_admin_csrf` echoed as `X-CSRF-Token`, and one stable `Idempotency-Key` for the logical action. A user retry after a network uncertainty reuses the key. |
| **S** | M plus fresh MFA step-up when required by the backend. On `STEP_UP_REQUIRED`, the UI prompts and repeats the original body with the same key.                                                                                     |
| **P** | Public login: credentials included; backend sets session and CSRF cookies. Login does not use CSRF or idempotency headers.                                                                                                        |
| **I** | Public one-time invitation acceptance: invitation token is path-scoped, an idempotency key is sent, and the backend does not require an admin session or CSRF proof for this public action.                                       |

Successful responses are read from `{ success: true, data, request_id }`. Errors are read from
`{ success: false, error: { code, message, details?, retryable, documentation_url }, request_id }`.
The client preserves `request_id`, displays a safe message by error code, keeps `ROUTE_NOT_FOUND`
separate from `RESOURCE_NOT_FOUND`, and never renders a failed query as an empty result. CSRF
recovery retries once with the original key; `IDEMPOTENCY_IN_PROGRESS` receives one bounded retry.
Money-moving payment corrections are never automatically resent after an uncertain transport
failure. MFA enrollment secrets and recovery-code responses are one-time values: same-key replay
returns `CREDENTIAL_REVEAL_REPLAY_UNAVAILABLE` rather than restoring a stored secret response.

## Supported operations

`UI/API` names refer to the page/component and typed operation in `lib/admin/api.ts`. Read queries
call those functions directly. Inline mutations use the same method/path/body through
`session-context.runMutation` so step-up continuation and user retries keep the same idempotency
key. `{id}` path values are URI-encoded; `:action` is appended to the encoded ID in the single
route segment expected by Fastify.

## Intentionally unsupported Control Panel surfaces

No Control Panel page or API client function deploys customer applications or calls customer Hosting,
Domains, VPS/HavenVPS, `/system/workers`, shell/terminal, hidden agent, dedicated compute, or
private-provider admin surfaces. `/deploy` manages only the Havenerr backend itself through fixed,
ROOT-only Admin actions; the browser receives no Git credential, shell, arbitrary PM2 target, or
filesystem path. Project databases and independent Quick Databases remain supported. Identity feature
flags are the only flags shown. Current plan snapshots omit retired `hosting.*` keys. Historical SQL
entitlement and price-history rows may remain preserved, but active schemas and runtime code ignore
them.

The project member permission editor is not part of this Admin Control Panel; those routes belong to
the customer Control plane and are not called by this frontend. If that separate customer UI is
maintained, its exact project permission set is `read`, `create`, `update`, `delete`, `invite`, and
`reveal_credentials`; it does not include `deploy`.
